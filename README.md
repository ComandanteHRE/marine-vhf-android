# Морская УКВ для RTL-SDR — версия 2 (Android)

Панель морской УКВ-радиостанции: каналы 1–28 и 60–88, канал 16, ▲▼, ввод канала/частоты, обзор всего
морского диапазона с быстрым переходом на найденную работу, мониторинг АИС (NMEA по TCP и UDP), запись звука.
Работает с RTL-SDR через приложение **«Rtl-sdr driver»** (`marto.rtl_tcp_andro`, v3.16 и новее).
Цель: Xiaomi/Redmi начиная с Redmi 9, включая Redmi Pad SE (Android 8.0+; панель для телефона и для планшета).

## Как получить APK (GitHub Actions)
1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки (корень репозитория — папка с `settings.gradle`).
2. Вкладка **Actions → Build APK → Run workflow** (или просто сделайте push).
3. Через 5–10 минут: страница запуска → **Artifacts → MarineVHF-apk** → внутри `app-release.apk`.
4. Скопируйте APK на телефон и установите (разрешите установку из файлового менеджера).

Сборка сама скачивает «Rtl-sdr driver» с F-Droid, проверяет SHA-256 и вшивает в APK (`assets/rtl_tcp_andro.apk`).
Если скачать не удалось, приложение загрузит драйвер само при первом запуске (нужен интернет).

## Первый запуск
1. Приложение предложит установить драйвер → «Установить» → разрешите «установку из этого источника» → подтвердите окно Android.
2. Подключите RTL-SDR через OTG-переходник.
3. «Подключить»: драйвер попросит доступ к USB — разрешите; вернувшись, приложение начнёт приём.
4. На Xiaomi один раз откройте подсказку: **Автозапуск — включить, Экономия заряда — «Нет ограничений»**, иначе MIUI/HyperOS
   может остановить приём при выключенном экране.

## Интерфейс
Оформление по присланным макетам: тёмная панель, янтарный дисплей, клавиши 1–9/·/0/ENT, красная «16», CLR, вертикальные
ползунки SQL и VOL, кнопки ЗАПИСЬ/АИС/СКАН/КАНАЛ-ЧАСТОТА/▲▼ и «Обзор каналов» внизу. Вертикальный вид — `res/layout`,
горизонтальный — `res/layout-land` (идентификаторы одинаковые). Вверху справа: СУДНО/БЕРЕГ, ПОДКЛ/ОТКЛ, ⚙ (настройки).
Журнал АИС — нажатие на строку «АИС: …» под графиком. Экран переходит в полноэкранный режим.

## Использование
- Кнопка КАНАЛ/ЧАСТОТА переключает тип ввода; цифры + ВВОД; частота: `156.8` — МГц, только цифры — кГц (`156800`).
- `16` — аварийный канал; ▲▼ — следующий/предыдущий канал; БЕРЕГ/СУДНО — сторона дуплексного канала.
- АИС: приём 161.975/162.025 МГц, строки `!AIVDM` — на TCP-порт (сервер на устройстве, по умолчанию 10110) и UDP
  (адрес и порт в настройках). Для OpenCPN и т. п.: TCP `адрес_телефона:10110`.
- Скан: проход по всему диапазону с индикацией; найденные каналы — кнопки под графиком, нажатие переключает приёмник.
- Запись: «● Запись» → файл в **Музыка/MarineVHF**. Форматы: AAC (M4A, по умолчанию), Opus (Ogg, Android 10+), WAV.

## Экономия энергии
- Экран по умолчанию может гаснуть (приём идёт в фоне через foreground-сервис); «Не гасить экран» — в настройках.
- Когда приложение свёрнуто, обновления экрана не посылаются вовсе; при открытом экране — не чаще ~7 раз в секунду,
  а дисплей и график перерисовываются только при изменении показаний.
- При закрытом шумоподавителе звук в AudioTrack не отправляется; запись по умолчанию только при открытом шумодаве.
- Отправка NMEA вынесена в отдельный поток: медленный TCP-клиент не тормозит приём; DNS для UDP-адреса — не в главном потоке.
- Громкость и SQL сохраняются один раз, когда палец отпущен, а не при каждом шаге ползунка.

## Что проверено, а что нет
Проверено на компьютере (JVM): DSP и декодер АИС (совпадение с Python-эталоном версии 1), ядро приёмника с имитацией
rtl_tcp-сервера, NMEA TCP/UDP, WAV-запись (`jvmtest/`).
**Не проверялось** (в среде разработки не было Android SDK): сборка Gradle, весь Android-слой (экран, сервис, звук,
запись AAC/Opus, установка драйвера, адрес загрузки F-Droid), работа на реальных телефонах. Ошибки при первой сборке
возможны — пришлите лог Actions, исправлю.
